# GitHub Copilot Instructions for OffGrid Platform

## 🎯 MISSION: ZERO DEFECTS, 100% QUALITY

This file defines the **non-negotiable** standards for all code changes—whether written by humans or AI assistants. Every modification MUST pass these gates before merge.

---

## 🚫 CRITICAL RULES (Never Ignore)

### Rule 1: TypeScript Strict Mode (Frontend)

- **ALL** TypeScript files must pass strict mode compilation
- `noImplicitAny`, `strictNullChecks`, `noUnusedLocals`, `noUnusedParameters` = **MANDATORY**
- No `@ts-ignore` or `@ts-expect-error` without explicit justification in comment

### Rule 2: ESLint & Prettier (Frontend)

- Zero ESLint errors allowed (warnings must be addressed or justified)
- Required rules:
  - `no-console: error` (except `console.warn`, `console.error`)
  - `@typescript-eslint/no-floating-promises: error`
  - `@typescript-eslint/no-unused-vars: error`
  - `eqeqeq: ["error", "always"]`
  - `curly: ["error", "all"]`
- All code must pass Prettier formatting

### Rule 3: Python Quality (Backend)

- **Black** formatting (line-length=100)
- **Ruff** linting (select: E, W, F, I, B, C4, UP)
- **MyPy** type checking with `disallow_untyped_defs: true`
- All functions must have type hints

### Rule 4: Test Coverage ≥90%

- Frontend (Jest): ≥90% lines, branches, functions, statements
- Backend (Pytest): ≥90% coverage
- No exceptions—write tests BEFORE marking work complete

### Rule 5: Fail-Fast Runtime

- **Node.js**: Process must terminate on `unhandledRejection` and `uncaughtException`
- **Python/FastAPI**: Global exception handler catches all errors; unhandled exceptions fail tests
- All async functions must have `.catch()` or `try/catch`

### Rule 6: Console & Network Error Detection (E2E)

- Playwright tests MUST fail on:
  - Any browser console errors
  - Any 4xx/5xx network responses (except whitelisted)
- Use fixtures in `/frontend/tests/fixtures/global-hooks.ts`

### Rule 7: Visual Regression

- Key pages must have screenshot snapshots
- CI compares against baseline; fails on unexpected visual changes
- Update snapshots with `npm run visual:update` (requires review)

### Rule 8: Link & Asset Integrity

- `/frontend/scripts/check-links.ts` must pass (exit code 0)
- Crawls entire site, fails on broken links or 404 assets
- Run before every merge

## 🧪 TESTING REQUIREMENTS

### Frontend Tests

1. **Unit Tests** (`/frontend/tests/unit/`)

   - Test React components in isolation
   - Test utility functions and logic
   - Use `@testing-library/react` for rendering
   - Mock external dependencies

2. **E2E Tests** (`/frontend/tests/e2e/`)

   - Test all routable pages load successfully
   - Verify critical user flows
   - Use Playwright with error detection hooks
   - Test on Chromium (CI), Firefox & WebKit (local)

3. **Visual Regression** (`/frontend/tests/visual/`)
   - Screenshot snapshots of key pages
   - Test desktop & mobile viewports
   - Test light & dark modes

### Backend Tests

1. **Unit Tests** (`/ai-service/tests/`)

   - Test business logic in isolation
   - Mock external APIs (OpenAI, Anthropic)
   - Use `pytest` with async support

2. **Integration Tests**

   - Test API endpoints with `TestClient`
   - Verify request/response contracts
   - Test error handling paths

3. **Health Checks**
   - All services must have `/health` endpoints
   - Test liveness, readiness, and startup probes

## 📋 CI/CD PIPELINE (Must Pass)

Order of execution in `.github/workflows/validate.yml`:

1. **Lint** → ESLint (frontend), Ruff (backend)
2. **Type Check** → TypeScript, MyPy
3. **Build** → `npm run build`, verify no compilation errors
4. **Unit/Integration Tests** → Jest (≥90%), Pytest (≥90%)
5. **Link Check** → `/frontend/scripts/check-links.ts`
6. **E2E Tests** → Playwright (console/network error detection)
7. **Visual Regression** → Screenshot diffs
8. **Coverage Report** → Fail if <90%

**Any failure = merge blocked.** No exceptions.

## 🤖 AI ASSISTANT GUIDELINES

When GitHub Copilot or other AI tools suggest code:

### ✅ DO:

- Always run `npm run validate` (frontend) or `pytest` (backend)
- Write tests for new functionality
- Follow existing patterns and conventions
- Use centralized config (`config.ts`, `settings.py`)
- Add error handling and logging
- Update documentation

### ❌ DON'T:

- Use `any` type without strong justification
- Suppress linting rules
- Skip writing tests
- Ignore TypeScript errors
- Use `console.log` (use `console.warn`/`console.error`)
- Commit unformatted code
- Merge without CI passing
